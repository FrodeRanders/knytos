# Native C runtime M1 qualification — 2026-11-24

## Result and scope

The authorized M1 scope is implemented on `feature/erlang-runtime`. Ten signed
C fixtures executed through normal authenticated deployment on AArch64 QEMU
11.1.3. The existing Rust service set booted and continued to admit applications
after C nonzero exit and abort. No kernel mechanism, ABI or resource limit was
changed. AtomVM and subsequent milestones have not started.

This qualifies the static C11, single-native-thread, no-TLS profile only.
The [build/runtime guide](../../../ports/libc/README.md) specifies supported
behavior; [architecture](../../architecture/c-runtime.md) separates it from
future ownership, reactor and thread requirements. See also the
[M0 discovery](../../plans/erlang-m0-discovery.md) and
[authorized scope](../../plans/erlang-m1-implementation.md).

## Implementation and inputs

- `crates/knytos-cabi`: Rust-owned startup and shared runtime allocator,
  private allocation-layout custody, bounded console, checked monotonic clock,
  explicit unavailable UTC, constructor/finalizer dispatch and terminal cleanup.
- `ports/libc`: C header, Picolibc bridge, cross-build/ELF checks and native
  fixtures. Picolibc 1.8.12 is pinned clean at
  `2ae376c6cdf4fef90ca2388ecf7a07457fa63cff`, with no upstream patches.
  TLS and libc malloc are disabled; errno is global in this one-thread profile.
- Apple Clang 21.0.0 (`clang-2100.3.34.2`), target `aarch64-none-elf`;
  Rust `nightly-2026-11-14`, compiler `5f4effd579500175af844241eb179e756190f1e7`,
  bundled LLVM 23.1.5 tools. Rust LLVM's archiver is explicitly used and forwarded
  into CMake compiler probes. Apple `ar` did not produce a usable cross archive.
- Final campaign kernel SHA-256:
  `00dd4a8e278e4058cbd47942172a18e52d1c740d6f7e75e0ab26ca8a34a5a6e0`.
  EDK2 firmware SHA-256:
  `47765fe344818cbc464b1c14ae658fb4b854f5c2ceffa982411731eb4865594d`.
  The immutable selected payload was extracted from the actual boot image.

The [retained evidence](../../plans/evidence/erlang-m1/summary.json) includes
resource results; [campaign manifest](../../plans/evidence/erlang-m1/run-4/result.json)
records QEMU arguments and initial boot/disk, kernel, firmware and signed image
hashes. Per-application build manifests record unsigned ELF hashes, compiler
versions and 57 source/configuration input hashes. Those inputs and fixture
source hashes were checked against the executed final builds. No private keys,
credentials, disks or ELF binaries are included in the evidence tree.

Build procedure reproducibility is qualified, not bit-identical regeneration
of randomized management credentials, boot images or signed deployment state.
Requalification is required with different compiler or libc inputs.

The native harness correlates each application launch's ASID with its result
and terminal marker. It waits for boot, synchronized management time, and the
DNS controller's capacity proposal before submitting each descriptor once.
It does not replay accepted deployment mutations or extend failed deadlines.

## Native measurements

All descriptors permitted one thread and 16 stack pages (65,536 bytes).
The configured runtime heap stayed at its existing 4 MiB limit.

| Fixture | Signed ELF bytes | Runtime heap peak bytes | Sampled stack bytes | Result |
| --- | ---: | ---: | ---: | --- |
| c-hello | 103,120 | 0 | 672 | 0 |
| c-memory | 112,664 | 4,133,241 | 1,456 | 0; allocator exhaustion handled |
| c-format | 107,424 | 0 | 768 | 0 |
| c-clock | 107,464 | 0 | 672 | 0 |
| c-startup | 108,456 | 135 | 736 | 0; one retained block freed |
| c-exit | 108,384 | 103 | 768 | 0; one retained block freed |
| c-error | 107,976 | 135 | 672 | 17; one retained block freed, domain aborted |
| c-abort | 102,960 | Unobserved | Unobserved | Expected abort |
| c-empty | 96,832 | 0 | 560 | 0; empty callback ranges |
| c-survivor | 103,120 | 0 | 672 | 0 after failures |

Every completed normal/nonzero-return cleanup reported `remaining_blocks=0`.
Heap peak comes from the runtime allocator's existing status record. Sampled
stack depth is the difference from Rust entry SP to the minimum SP observed
at selected Rust boundary calls. It excludes unsampled deeper C/libc/Rust
frames and is a lower bound, not a full high-water value. Successful execution
within a signed 64 KiB limit does not establish the smallest safe stack.
Pressure-test heap use is intentionally near exhaustion and is not a VM minimum.

Representative final serial output, retained in full in

## Validation commands

From the checkout:

```sh
python3 ports/libc/run-tests.py --picolibc-source /path/to/clean/picolibc \
  --output target/c-runtime/native-validation
cargo clippy --locked -p knytos-cabi --release \
  --target crates/knytos-services/aarch64-unknown-none.json \
  -Z build-std=core,alloc,compiler_builtins -- -D warnings
cargo fmt --all -- --check
python3 -m py_compile ports/libc/build.py ports/libc/run-tests.py
python3 scripts/tests/test-ci-runtime-inputs.py
```

The native campaign builds bundled services through `scripts/run-aarch64.sh`
and its standard `scripts/build-knytos-services.sh` path. All ten cases and
three expected negative controls passed. The supplementary POSIX `open`
build failed with `undefined symbol: open`, as required; the final harness
now uses that concrete unsupported function instead of the synthetic import.

Host tests were invoked from `/private/tmp` to avoid the freestanding root
Cargo configuration, with the toolchain explicitly pinned:

```sh
cargo +nightly-2026-11-14 test --locked \
  --manifest-path /absolute/path/to/knytos/Cargo.toml \
  -p knytos-cabi -p knytos-rt -p knytos-app -p knytos-app-sitas \
  --all-features --lib
```

89 tests passed (4 C ABI, 66 runtime, 14 application, 5 Sitas application).
Clippy with warnings denied, workspace formatting, Python compilation and six
CI runtime-input tests passed. Captured logs are in the evidence directory.

## Failed runs and limitations

Failed campaigns remain separate from the passing repeat:

| Capture | Observation and disposition |
| --- | --- |
| run-1 | Sandbox rejected the QMP socket; guest exited before tests. Rerun with socket/network permission. No runtime qualification. |
| run-2 | Boot succeeded; first deployment returned HTTP 503/error -2 before DNS leader/capacity readiness. No C application executed. Added a readiness gate before submission. |
| run-3 | c-hello printed CABI FINI before main, then EL0 instruction abort at address zero; captured all four CPUs. Incorrect nonzero Rust extern-static boundary declarations allowed the optimizer to assume an empty constructor range was nonempty. Changed boundaries to zero-sized symbols; made constructor-test state volatile and added an independent empty-array fixture. |
| Preparation | Cross archive initially unusable with Apple ar; later CMake try-compile needed the explicit LLVM archiver forwarded. Compile/link errors exposed an invalid literal alignment test, fflush's nonnull contract, and Picolibc's private exit handler. Corrected before execution. A host test invocation with the default older nightly failed on existing allocator_ext usage; the explicit repository toolchain passed. |

The [run-3 capture](../../plans/evidence/erlang-m1/run-3/result.json) retains
artifact identities, serial, QMP register observations and LLDB output separately.
The final repeat passed the corrected startup and empty-array paths. These
observations do not resolve the earlier independent
[CI minimal-boot incident](../investigations/2026-11-24-aarch64-minimal-timeout.md).

No C capability/resource API, asynchronous IPC, thread API, TLS template,
POSIX environment or VM exists in this profile. `_Exit` and recursive exit
have defined implementation paths but no independent native fixture in this
campaign. Abort intentionally skips normal C callbacks; kernel domain
retirement is not proved complete by a C terminal log or by local heap release.
The result does not qualify general cancellation, production credentials,
complete stack high-water, or AtomVM/ERTS package and memory fit.

The next proposed scope is M2: acquire the independently pinned compatible
OTP 27.3.4.19 compiler, build the interpreter-only AtomVM 0.6.6 platform adapter,
and measure an authenticated minimal module closure with timers and scheduler
wakes. Review this M1 result before beginning that work.
