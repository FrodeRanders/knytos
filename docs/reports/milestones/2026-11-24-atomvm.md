# AtomVM M2 qualification — 2026-11-24

## Result and authorized scope

M0/M1 was committed as `53b253a7b5b806577012ca460ba81fd9481e0748` and pushed
to `origin/feature/erlang-runtime` at the user's request. The user then authorized
[M2](../../plans/erlang-m2-implementation.md). The resulting single-scheduler
AtomVM interpreter executed authenticated Erlang modules in a normal AArch64
EL0 domain. It printed hello, received a prequeued message, blocked for a timed
receive and returned `ok` through native C termination.

The native campaign passed all 12 cases: ten retained C fixtures, AtomVM hello,
and an expected explicit unavailable-UTC failure. A survivor C application
launched after the VM abort. No kernel mechanism, ABI or limit was changed.
This is M2 qualification, not general OTP, SMP, native service NIF or ERTS support.
M3 has not started.

## Implementation and patch inventory

| Category | Implementation |
| --- | --- |
| Build integration | `ports/atomvm/build.py` reads the pinned upstream core source list, generates upstream lookup tables, builds host tools, invokes the compatible compiler and PackBEAM, embeds the package and uses the M1 ELF builder. The C builder accepts include directories and static archives and records their hashes. |
| Knytos platform | `ports/atomvm/main.c` and `sys.c`: startup, static NIF identity, signed embedded module lookup, monotonic time and a single CQ reactor. |
| Generic runtime | Borrowed CQ-zero wait/wake C ABI over `knytos_rt::cq::wait`, with distinct readiness, deadline, admission, invalid-request and shutdown outcomes. Lifecycle is checked before and after waiting. |
| Upstream portability patches | None. Clean upstream source remains unchanged; `_POSIX_C_SOURCE=200809L` exposes Picolibc's string-only `strdup`, without enabling OS feature macros. |
| VM semantics patches | None. The adapter implements the selected release's existing interfaces. |

The [port guide](../../../ports/atomvm/README.md) is the build and behavior
contract. The [C guide](../../../ports/libc/README.md),
[CQ reference](../../reference/cq-wait.md) and
[architecture](../../architecture/c-runtime.md) describe the shared ownership
and waiting boundaries.

The target is interpreter-only, one scheduler, one native thread, no ELF TLS,
no native task drivers, dynamic native loading, external module path, sockets
or filesystem. It requests no service capabilities. The immutable package
bytes live in read-only ELF memory covered by ordinary executable signing.
Package metadata and VM allocations use the tracked C heap. No capability
number is adopted or owned by C.

The pinned no-SMP scheduler does not call `sys_signal`. A C wake operation posts
a real kernel CQ generation before the sole consumer waits, and the native
fixture verifies it is retained. The VM scheduler keeps absolute timer expiry,
rechecks runnable work after wakes, and waits on the native CQ watchdog.
Fractional remaining milliseconds round up to avoid a busy poll. Rejected
wait admission and shutdown abort explicitly; neither restarts timers or
discharges a future operation owner. SMP notifications remain unqualified.

confirmed kernel domain retirement.

## Commands and failed preparations

The [port guide](../../../ports/atomvm/README.md) gives exact OTP configure,
host build, target build and signed-run commands. The native campaign was:

```sh
python3 ports/libc/run-tests.py --picolibc-source /path/to/picolibc \
  --atomvm-elf target/atomvm/atomvm-hello.elf \
  --atomvm-utc-elf target/atomvm/atomvm-utc.elf \
  --output target/atomvm/native-validation
```

The harness uses the standard bundled-services build, fresh disk, readiness
gate and one authenticated deployment submission per fixture, with ASID/result
correlation. The same hello package on the pinned generic Unix interpreter
printed `generic_unix`, hello, `elapsed_ms=26` and `Return value: ok`.

89 host tests passed (4 C ABI, 66 runtime, 14 application, 5 Sitas application),
plus six CI runtime-input tests. Target C ABI Clippy with warnings denied,
workspace `cargo fmt --all -- --check`, Python compilation and diff whitespace
checks passed. The build retains upstream warnings for three unused no-SMP
parameters and generated gperf non-prototype functions; these are recorded,
not represented as a warning-free upstream C build.

Two failed preparations are retained separately: the first target build could
not see `strdup` under strict C11 until the libc feature declaration was enabled;
the first reference fixture asserted `knytos` on Unix and failed with
`{badmatch,generic_unix}`. The corrected fixture allows the expected reference
identity while the native harness specifically requires `knytos`. No failed
M2 native campaign occurred. The failed reference package had SHA-256
`4af10470e338f47fdbf3e0a3c800e7e48ba6fa80dc0b1bd680b4bf6634249719`;
its bytes were replaced by the corrected rebuild, so the retained crash log
and observed hash are the available evidence for that preparation.
The prior independent CI minimal-boot incident
remains unresolved; this pass supplies no causal explanation for it.

## Remaining limits and next scope

Wall-clock calls abort because this release's void hook cannot express
unavailable UTC; a reviewed authorized service/quality policy is required.
SMP/TLS, arbitrary file or native-service resources, selectable events,
external packages, dynamic NIFs, ERTS, distributed execution and checkpointing
are absent. General semantic, timer cancellation/overflow/race and resource
pressure coverage belong to M3/M4; a short receive and queued-message test
do not qualify those categories. Reusing a VM within one live C domain would
need separate complete teardown and allocation accounting qualification.

Review this M2 result before beginning M3's Erlang semantics and native
thread/synchronization work. Keep single-scheduler semantic qualification
separate from the larger TLS/SMP contract.
